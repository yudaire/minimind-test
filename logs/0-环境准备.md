# 01 环境准备

## 目标
搭建 MiniMind 训练环境：本地工具链、远程 GPU 服务器、Python 虚拟环境。

## 环境信息

| 项目 | 配置 |
| :--- | :--- |
| 平台 | AutoDL |
| GPU | RTX 4090 / 24GB |
| 计费方式 | 按量计费 |
| 数据盘 | 70GB，挂载 `/root/autodl-tmp` |
| 镜像 | PyTorch 2.8.0 / Python 3.12 / CUDA 12.8 / Ubuntu 22.04 |
| 虚拟环境 | conda，Python 3.10，路径 `/root/autodl-tmp/minimind_env` |
| 核心依赖 | PyTorch 2.6.0+cu124 |

## 本地工具

| 工具 | 用途 |
| :--- | :--- |
| Git | 版本控制 |
| FlashGit | GitHub 连接加速 |
| VS Code | 代码编辑与远程连接 |
| Remote - SSH 扩展 | 连接远程服务器（Microsoft 出品） |

## 关键命令

### 创建虚拟环境
```bash
conda create -p /root/autodl-tmp/minimind_env python=3.10 -y
source /root/miniconda3/etc/profile.d/conda.sh
conda activate /root/autodl-tmp/minimind_env
```

### 安装 PyTorch 2.6.0
```bash
pip install torch==2.6.0 torchvision==0.21.0 --index-url https://download.pytorch.org/whl/cu124
```

### 安装项目依赖
```bash
cd /root/autodl-tmp/minimind
pip install -r requirements.txt -i https://mirrors.aliyun.com/pypi/simple
```

### 环境验证
```bash
nvidia-smi
python --version
python -c "import torch; print(torch.__version__, torch.cuda.is_available())"
df -h /root/autodl-tmp
mount | grep autodl
```

## 问题与排查

### 问题 1：VS Code 添加 SSH 主机报 EPERM
**报错：**
```
A system error occurred (EPERM: operation not permitted, open 'C:\ProgramData\ssh\ssh_config')
```
**原因：** VS Code 默认写入系统目录 `C:\ProgramData`，普通用户无权限。

**解决：** 添加主机时手动选择用户目录下的 `.ssh/config`，即 `C:\Users\用户名\.ssh\config`。

**验证：** 重新添加主机后连接成功。

---

### 问题 2：数据盘在 `df -h` 中未直接显示
**现象：** `df -h` 输出中看不到独立的 `/root/autodl-tmp` 分区。

**排查：**
```bash
mount | grep autodl
```
输出确认 `/dev/md0` 已挂载到 `/root/autodl-tmp`。

**结论：** 数据盘挂载正常，`df -h` 因输出行数限制未显示。

---

### 问题 3：SciPy 与 NumPy 版本冲突
**报错：**
```
ValueError: All ufuncs must have type `numpy.ufunc`. Received (<ufunc 'sph_legendre_p'>, ...)
```

**排查过程：**
1. 初始怀疑 NumPy 版本过新，降级至 1.26.4，报错依旧。
2. 检查 SciPy 版本为 1.17.1，与 NumPy 1.26.4 存在二进制兼容性问题。
3. 分析：系统默认环境 Python 3.12 与项目推荐的 Python 3.10 不一致，依赖解析出现冲突。

**解决：** 创建独立虚拟环境 `minimind_env`（Python 3.10），重新安装 PyTorch 2.6.0 和项目依赖，SciPy 导入正常。

**验证：**
```bash
python -c "from scipy.special import sph_legendre_p; print('scipy OK')"
```
输出：`scipy OK`

---



### 问题 5：训练中终端断开
**现象：** 移动电脑时网络中断，VS Code 终端与服务器断开，看不到实时训练输出。

**确认：** SwanLab 曲线仍在更新，`nvidia-smi` 显示 GPU 占用正常，训练进程未死。

**结论：** 训练进程在服务器后台继续运行，仅终端连接断开。

**建议：** 长时间训练前使用 `tmux`：
```bash
tmux new -s train
# 在 tmux 内启动训练
# 按 Ctrl+B 再按 D 脱离
# 重连后：tmux attach -t train
```

## 结果
- 虚拟环境创建完成，位于 `/root/autodl-tmp/minimind_env`。
- PyTorch 2.6.0+cu124，CUDA 可用。
- 项目依赖安装完成，SciPy 导入正常。
- GPU、数据盘均正常。

## 关键点
- 系统盘 30GB 放系统和环境，数据盘 70GB 放代码、数据、模型。
- 虚拟环境建于数据盘，避免系统盘空间不足。
- 每次新开终端需先执行：
```bash
source /root/miniconda3/etc/profile.d/conda.sh
conda activate /root/autodl-tmp/minimind_env
```
